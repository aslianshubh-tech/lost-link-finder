0500 | def text_similarity(first: str | None, second: str | None) -> float:
0501 |     a, b = normalized(first), normalized(second)
0502 |     if not a or not b:
0503 |         return 0.0
0504 |     sequence = SequenceMatcher(None, a, b).ratio()
0505 |     left, right = tokens(a), tokens(b)
0506 |     overlap = len(left & right) / max(len(left | right), 1)
0507 |     return max(sequence, overlap)

0001 | # LostLink
0002 | 
0003 | LostLink is a college lost and found system. Students can report belongings they lost or found, browse campus reports, and see transparent possible matches between the two kinds of reports.
0004 | 
0005 | ## Problem statement
0006 | 
0007 | Students often lose ID cards, calculators, books, notebooks, bags, water bottles, earphones, keys, and other belongings on campus. A different student may find the item but have no reliable way to identify its owner. LostLink gives both reports one shared place.
0008 | 
0009 | ## Objective
0010 | 
0011 | The objective is to make returning belongings easier without pretending to use artificial intelligence. LostLink uses an understandable rule-based score so a student can see why two reports may match.
0012 | 
0013 | ## Features
0014 | 
0015 | - Empty SQLite database on first start (no demo users or sample reports)
0016 | - Account registration with hashed passwords
0017 | - Login, logout, and session-protected personal pages
0018 | - Lost and found item reports with optional local image uploads
0019 | - Browse pages with item, category, color, location, and date filters
0020 | - Matching across category, name, color, location, date, time, and description
0021 | - High match (80–100%) and possible match (60–79%) levels
0022 | - Human-readable reasons for each possible match
0023 | - Personal dashboard, report management, and resolved status
0024 | - Authorization checks so only the owner can resolve their report
0025 | - Responsive student-friendly interface
0026 | 
0027 | ## Technology
0028 | 
0029 | - Python
0030 | - Flask
0031 | - SQLite
0032 | - HTML5 templates
0033 | - CSS3
0034 | - Vanilla JavaScript
0035 | 
0036 | ## Database design
0037 | 
0038 | - `users`: account information and hashed password
0039 | - `lost_items`: reports for items a student lost
0040 | - `found_items`: reports for items a student found
0041 | - `matches`: score and explanation for each lost/found pair
0042 | 
0043 | All report tables reference `users` with foreign keys. Created timestamps are stored automatically.
0044 | 
0045 | ## Matching algorithm
0046 | 
0047 | Each pair of reports can score up to 100 points:
0048 | 
0049 | | Detail | Points |
0050 | | --- | ---: |
0051 | | Category | 20 |
0052 | | Item name similarity | 20 |
0053 | | Color | 15 |
0054 | | Location similarity | 15 |
0055 | | Date proximity | 10 |
0056 | | Time proximity | 10 |
0057 | | Description similarity | 10 |
0058 | 
0059 | The app shows:
0060 | 
0061 | - 80–100: High match
0062 | - 60–79: Possible match
0063 | - Below 60: kept out of the prominent matches page
0064 | 
0065 | The score is only one part of the result. Each match also lists the details that contributed points, such as “Same category” or “Similar description.”
0066 | 
0067 | ## Folder structure
0068 | 
0069 | ```text
0070 | app.py
0071 | database: SQLite file created in instance/
0072 | templates/          HTML pages
0073 | static/css/         styles
0074 | static/js/          small browser interactions
0075 | uploads/            local report images
0076 | requirements.txt
0077 | ```
0078 | 
0079 | ## Installation
0080 | 
0081 | 1. Make sure Python 3.11 or newer is available.
0082 | 2. Install the dependency:
0083 | 
0084 |    ```bash
0085 |    pip install -r requirements.txt
0086 |    ```
0087 | 
0088 | The first run creates `instance/lostlink.sqlite3` and `uploads/`. No sample records are inserted.
0089 | 
0090 | ## How to run
0091 | 
0092 | ```bash
0093 | python app.py
0094 | ```
0095 | 
0096 | The app uses `PORT` when it is provided by the environment and otherwise runs on port 5000.
0097 | 
0098 | ## How to test manually
0099 | 
0100 | 1. Open the home page and confirm the app has no fake counts or sample reports.
0101 | 2. Register two accounts and sign in.
0102 | 3. Submit one lost report and one found report with similar details.
0103 | 4. Open Possible matches and read the score reasons.
0104 | 5. Check the browse filters and item details pages.
0105 | 6. Mark one of your own reports resolved.
0106 | 7. Confirm another account cannot resolve that report.
0107 | 8. Sign out and confirm protected pages redirect to sign in.
0108 | 
0109 | ## Future improvements
0110 | 
0111 | - Campus email-domain verification
0112 | - Moderator review for sensitive items such as ID cards
0113 | - Email notifications for strong matches
0114 | - Optional campus building directory for better location matching
0115 | - A report hand-off workflow when both students confirm a return
